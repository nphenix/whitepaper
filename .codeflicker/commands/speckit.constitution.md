## 概述

用户在触发消息中 `/speckit.constitution` 后输入的文本**就是**章程更新描述. 假设你始终可以在本次对话中访问它, 即使下面字面上显示 `$ARGUMENTS`. 除非用户提供了空命令, 否则不要要求用户重复.

基于该章程更新需求, 执行以下操作:

1. **加载现有章程**
   - 从 `.specify/memory/constitution.md` 加载现有章程
   - 理解章程的结构和当前内容

2. **分析更新需求**
   - 识别需要更新的具体原则或条款
   - 理解更新的动机和目标
   - 评估更新对项目的影响

3. **制定更新方案**
   - 设计章程更新的具体内容
   - 考虑更新的合理性和必要性
   - 确保更新符合项目的长期发展目标

4. **更新章程文件**
   - 修改 `.specify/memory/constitution.md` 文件
   - 更新版本号和日期
   - 在版本历史中记录变更
   - 更新同步影响报告

5. **验证更新内容**
   - 检查更新后的内容是否清晰、合理
   - 确认更新是否与其他文档一致
   - 验证更新是否符合项目需求

6. **更新相关模板**
   - 检查并更新 `.specify/templates/` 下的相关模板
   - 确保模板与新章程保持一致
   - 记录模板的更新情况

7. **生成更新报告**
   - 创建章程更新报告
   - 详细说明变更内容和原因
   - 评估更新的影响范围
   - 提供实施建议

8. **报告完成情况**
   - 包括更新后的章程文件路径
   - 总结更新的主要内容
   - 说明更新的理由和影响

## 通用指南

### 章程更新原则
- **必要性**: 只有在确实需要时才更新章程
- **合理性**: 更新应该基于合理的理由和充分的考虑
- **一致性**: 更新应该与其他项目文档保持一致
- **前瞻性**: 更新应该考虑项目的长期发展
- **参与性**: 重大更新应该征求团队意见

### 更新类型
- **文字澄清**: 修正表述不清或有歧义的内容
- **原则新增**: 添加新的原则或条款
- **原则修改**: 修改现有原则的表述或内容
- **原则删除**: 删除不再适用的原则
- **结构调整**: 调整章程的结构或组织方式

### 版本管理
- **语义化版本**: 遵循语义化版本规范
  - MAJOR: 删除/重写原则
  - MINOR: 新增或大幅扩展
  - PATCH: 文字澄清
- **版本历史**: 详细记录每个版本的变更
- **影响报告**: 说明更新对相关文件的影响

### 更新流程
- **提案阶段**: 明确更新需求和理由
- **分析阶段**: 评估更新的影响和必要性
- **制定阶段**: 设计具体的更新方案
- **实施阶段**: 执行更新并验证结果
- **沟通阶段**: 向团队传达更新内容

## 附加要求

### 影响评估
- 评估章程更新对项目各方面的潜在影响
- 识别需要同步更新的相关文档
- 考虑对团队工作流程的影响
- 评估对项目治理的影响

### 利益相关者沟通
- 识别受更新影响的关键利益相关者
- 在更新前征求相关人员的意见
- 确保更新得到必要的批准
- 及时向团队传达更新内容

### 文档同步
- 更新所有引用章程的相关文档
- 确保模板和指南与新章程一致
- 检查工具配置是否需要调整
- 验证培训材料是否需要更新

### 执行监督
- 建立章程执行的监督机制
- 定期检查章程的执行情况
- 收集团队对章程的反馈
- 准备章程的后续优化

### 知识管理
- 记录章程更新的决策过程
- 保存相关的讨论和反馈
- 建立章程解释的参考文档
- 积累章程管理的经验

## 更新工作流程

### 阶段 1: 需求分析
1. 明确章程更新的具体需求
2. 分析更新的背景和动机
3. 识别需要修改的具体条款
4. 评估更新的必要性和合理性

### 阶段 2: 方案设计
1. 制定章程更新的具体方案
2. 设计新的条款表述
3. 评估方案的可行性和影响
4. 准备更新的理论依据

### 阶段 3: 文件更新
1. 修改章程的主体内容
2. 更新版本号和日期
3. 完善版本历史记录
4. 更新同步影响报告

### 阶段 4: 相关文档更新
1. 更新 `.specify/templates/` 下的模板
2. 更新相关的指南和文档
3. 调整工具配置（如需要）
4. 更新培训材料（如需要）

### 阶段 5: 验证和沟通
1. 验证更新内容的正确性
2. 向团队传达更新内容
3. 收集团队的反馈意见
4. 准备后续的执行监督

## 注意事项

- **谨慎更新**: 章程是项目的基础，更新应该谨慎进行
- **充分沟通**: 重大更新前应该充分征求团队意见
- **记录完整**: 详细记录更新的原因、过程和结果
- **保持一致**: 确保更新后的内容与项目目标一致
- **及时同步**: 及时更新所有相关的文档和资源

## 章程权威性

- 本章程在项目中具有最高权威
- 所有项目活动都应该遵循章程的原则
- 章程冲突应该优先通过调整具体实践来解决
- 只有在特殊情况下才考虑修改章程本身

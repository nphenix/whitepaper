## 用户输入

```text
$ARGUMENTS
```

在继续之前, 你**必须**考虑用户输入(如果不为空).

## 概述

用户在触发消息中 `/speckit.implement` 后输入的文本**就是**实施描述. 假设你始终可以在本次对话中访问它, 即使下面字面上显示 `$ARGUMENTS`. 除非用户提供了空命令, 否则不要要求用户重复.

基于该任务清单, 执行以下操作:

1. **加载任务清单**
   - 从 `specs/[feature]/tasks.md` 加载任务清单
   - 确认任务清单已通过完整性验证

2. **分析任务依赖**
   - 识别任务之间的依赖关系
   - 确定任务的执行顺序
   - 识别可以并行执行的任务
   - 评估任务的复杂度和风险

3. **准备实施环境**
   - 检查开发环境是否就绪
   - 确认所需的依赖和工具已安装
   - 准备必要的配置文件
   - 设置版本控制分支（如需要）

4. **按优先级执行任务**
   - **P1 (必须)**: 优先完成核心功能任务
   - **P2 (重要)**: 完成重要功能任务
   - **P3 (可选)**: 完成增强功能任务（根据时间和资源决定）
   - 严格按照任务的验收标准执行

5. **代码实现**
   - 遵循项目的编码规范
   - 使用适当的架构模式
   - 确保代码的可读性和可维护性
   - 添加必要的注释和文档

6. **单元测试**
   - 为每个功能编写单元测试
   - 确保测试覆盖率达标
   - 测试应该覆盖正常情况和边界情况
   - 测试代码应该清晰、可维护

7. **集成测试**
   - 测试模块间的交互
   - 验证系统整体功能
   - 测试异常情况的处理
   - 确保数据流正确

8. **文档更新**
   - 更新相关的技术文档
   - 更新 API 文档
   - 更新使用说明
   - 记录重要的实现细节

9. **代码审查准备**
   - 确保代码符合质量标准
   - 准备变更说明
   - 整理相关的文档
   - 准备回答审查问题

10. **验证实施结果**
    - 对照任务清单检查完成情况
    - 验证每个任务的验收标准
    - 确认功能是否按预期工作
    - 识别任何未解决的问题

11. **生成实施报告**
    - 记录实施过程中的关键决策
    - 总结遇到的问题和解决方案
    - 评估实施结果与预期的符合程度
    - 提供改进建议

12. **报告完成情况**
    - 包括实现的文件列表
    - 总结完成的任务
    - 列出遇到的问题和解决方案
    - 说明下一阶段（测试、部署等）的准备就绪状态

## 通用指南

### 实施原则
- **质量第一**: 始终优先考虑代码质量和系统稳定性
- **循序渐进**: 按照任务的依赖关系和优先级逐步实施
- **持续集成**: 频繁地集成和测试代码变更
- **文档同步**: 实现过程中及时更新相关文档

### 代码质量要求
- 遵循项目的编码规范和最佳实践
- 确保代码的可读性、可维护性和可扩展性
- 使用适当的注释解释复杂的逻辑
- 避免重复代码，提取公共功能

### 测试策略
- 采用测试驱动开发（TDD）或行为驱动开发（BDD）
- 确保测试覆盖所有关键功能
- 测试应该快速、可靠、可重复
- 测试失败时应该提供清晰的错误信息

### 版本控制
- 使用有意义的提交信息
- 保持提交历史的清晰和整洁
- 避免在提交中包含不必要的文件
- 及时推送代码到远程仓库

### 问题处理
- 及时识别和记录实施中的问题
- 采用系统化的方法分析问题根源
- 与团队成员协作解决复杂问题
- 从问题中学习并改进实施方法

## 附加要求

### 性能考虑
- 在实现过程中考虑性能影响
- 识别潜在的性能瓶颈
- 采用适当的优化策略
- 进行性能测试和监控

### 安全性
- 遵循安全编码最佳实践
- 识别和防范常见的安全漏洞
- 对敏感数据进行适当的保护
- 进行安全测试和审查

### 可维护性
- 编写清晰、简洁的代码
- 使用有意义的命名
- 保持模块间的低耦合
- 提供完整的文档

### 可扩展性
- 考虑未来的扩展需求
- 使用灵活的架构设计
- 避免过度设计
- 为未来的变更预留空间

### 团队协作
- 与团队成员保持良好的沟通
- 及时分享实施进展
- 协助解决团队中的技术问题
- 参与代码审查和知识分享

### 时间管理
- 合理估算任务所需的时间
- 优先处理重要的任务
- 及时报告进度和风险
- 灵活调整实施计划

## 实施流程

### 阶段 1: 准备工作
1. 仔细阅读任务清单
2. 理解每个任务的目标和要求
3. 准备实施环境
4. 制定详细的实施计划

### 阶段 2: 核心功能实现
1. 优先实现 P1 级别的任务
2. 确保每个任务都通过测试
3. 及时更新相关文档
4. 定期进行代码审查

### 阶段 3: 重要功能实现
1. 实现 P2 级别的任务
2. 进行集成测试
3. 优化性能和用户体验
4. 完善文档

### 阶段 4: 增强功能实现（可选）
1. 根据时间和资源决定是否实现 P3 任务
2. 实现有价值的增强功能
3. 进行最终的测试和优化
4. 准备部署

### 阶段 5: 验证和总结
1. 全面验证实施结果
2. 生成实施报告
3. 总结经验教训
4. 准备下一阶段的工作

## 注意事项

- **保持专注**: 专注于当前任务，避免分心
- **及时沟通**: 遇到问题时及时与团队沟通
- **记录完整**: 详细记录实施过程中的关键决策和问题
- **质量保证**: 始终把质量放在首位
- **持续改进**: 从每次实施中学习，不断改进工作方法

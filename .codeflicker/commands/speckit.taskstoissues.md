## 用户输入

```text
$ARGUMENTS
```

在继续之前, 你**必须**考虑用户输入(如果不为空).

## 概述

用户在触发消息中 `/speckit.taskstoissues` 后输入的文本**就是**任务到问题转换描述. 假设你始终可以在本次对话中访问它, 即使下面字面上显示 `$ARGUMENTS`. 除非用户提供了空命令, 否则不要要求用户重复.

基于该任务清单, 执行以下操作:

1. **加载任务清单**
   - 从 `specs/[feature]/tasks.md` 加载任务清单
   - 确认任务清单已通过完整性验证

2. **分析任务结构**
   - 识别任务的优先级（P1、P2、P3）
   - 理解任务的依赖关系
   - 提取任务的详细描述和验收标准
   - 识别任务的估算时间和负责人

3. **设计 Issue 模板**
   - 创建标准的 Issue 模板
   - 包含任务标题、描述、验收标准
   - 包含优先级、标签、里程碑信息
   - 包含相关链接和参考资料

4. **转换任务为 Issues**
   - 为每个任务创建对应的 GitHub Issue
   - 使用清晰、具体的 Issue 标题
   - 填写详细的 Issue 描述
   - 设置适当的优先级标签
   - 添加相关的里程碑

5. **配置 Issue 属性**
   - 设置 Issue 的标签（如 bug、feature、enhancement 等）
   - 分配给相应的负责人
   - 设置截止日期（如果适用）
   - 添加相关的项目板列

6. **建立依赖关系**
   - 在 Issues 之间建立依赖链接
   - 使用 blocking/blocked by 关系
   - 确保依赖关系的可视化
   - 考虑使用项目管理工具增强依赖管理

7. **创建 Epic 或 Project**
   - 如果任务较多，考虑创建 Epic 或 Project
   - 将相关的 Issues 组织到一起
   - 设置项目的目标和里程碑
   - 建立项目的状态跟踪机制

8. **生成转换报告**
   - 记录创建的 Issues 数量
   - 总结 Issues 的分布情况
   - 说明依赖关系的建立
   - 提供后续跟踪建议

9. **报告完成情况**
   - 包括创建的 Issues 列表
   - 总结转换的主要内容
   - 说明 Issues 的组织结构
   - 提供使用建议

## 通用指南

### Issue 创建原则
- **清晰性**: Issue 标题和描述应该清晰、具体
- **完整性**: 包含任务的所有关键信息
- **可操作性**: Issue 应该可以直接执行
- **可追踪性**: 每个 Issue 都应该可以追踪进度

### 优先级设置
- **P1 (必须)**: 使用 high 或 critical 优先级
- **P2 (重要)**: 使用 medium 优先级
- **P3 (可选)**: 使用 low 优先级
- 确保优先级与任务清单一致

### 标签使用
- 使用统一的标签命名规范
- 标签应该有意义且易于理解
- 避免使用过多的标签
- 定期审查和清理标签

### 里程碑管理
- 将任务按里程碑分组
- 设置合理的里程碑时间
- 确保里程碑目标明确
- 跟踪里程碑的完成情况

### 依赖关系管理
- 清晰标识任务间的依赖关系
- 使用 blocking/blocked by 语法
- 考虑使用项目管理工具增强管理
- 定期审查依赖关系的有效性

## 附加要求

### Issue 模板设计
- 创建可复用的 Issue 模板
- 包含标准的字段和格式
- 提供填写说明
- 考虑不同类型的 Issue 模板

### 批量操作
- 考虑使用 GitHub API 进行批量创建
- 使用脚本自动化转换过程
- 验证批量操作的结果
- 处理批量操作中的错误

### 项目板设置
- 设置适合团队工作流的项目板
- 定义清晰的列和状态
- 配置自动化的状态转换
- 设置适当的权限

### 通知和提醒
- 配置适当的 Issue 通知
- 设置截止日期提醒
- 建立定期检查机制
- 确保团队成员及时响应

### 跟踪和报告
- 建立 Issue 进度跟踪机制
- 定期生成进度报告
- 监控 Issue 的完成情况
- 识别和解决阻塞问题

### 团队协作
- 确保团队成员理解 Issue 系统
- 培训团队成员使用 GitHub
- 建立 Issue 讨论的规范
- 鼓励及时更新 Issue 状态

## 转换流程

### 阶段 1: 准备工作
1. 仔细阅读任务清单
2. 理解任务的结构和要求
3. 设计 Issue 模板
4. 准备转换工具

### 阶段 2: 任务分析
1. 提取任务的详细信息
2. 分析任务的优先级
3. 识别任务的依赖关系
4. 确定任务的负责人

### 阶段 3: Issue 创建
1. 为每个任务创建 Issue
2. 填写 Issue 的详细信息
3. 设置优先级和标签
4. 建立依赖关系

### 阶段 4: 组织和管理
1. 创建相关的 Milestone
2. 设置 Project Board
3. 配置自动化规则
4. 建立跟踪机制

### 阶段 5: 验证和报告
1. 验证 Issue 创建的正确性
2. 生成转换报告
3. 向团队介绍 Issue 系统
4. 准备后续的跟踪工作

## 注意事项

- **一致性**: 确保 Issue 的格式和内容与任务清单一致
- **准确性**: 准确转换任务的所有关键信息
- **完整性**: 不遗漏任何重要的任务或细节
- **可维护性**: 设计易于维护和更新的 Issue 结构
- **团队协作**: 与团队成员沟通，确保他们理解新的 Issue 系统

# 功能规范: 多 Agent 协作的文档处理与生成系统

**功能分支**: `001-multi-agent-doc-system`
**创建时间**: 2025-12-05
**状态**: 草稿
**输入**: 用户描述: "这是一个web应用，主要使用python 3.12，基于langchain1.0，构建一个多 Agent 协作的文档处理与生成系统，核心模块包括：本地知识库与数据抽取 - 搭建结构化知识库，支持文档解析、内容索引与检索。结构优化 Agent - 对用户输入的框架/大纲进行结构化增强。信息检索 Agent - 从本地知识库中匹配相关内容，并提供真实引用。草稿生成 Agent - 综合大纲与信息源，生成可交付文稿并支持基础润色。"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 文档预处理与清洗 (优先级: P1)

用户上传各种格式的文档后，系统需要能够识别文档格式，加载文档内容，并进行清洗处理（去除无关内容、格式化、标准化等），为后续的解析和索引做准备。这是文档处理流程的第一步，确保文档内容的质量和一致性。

**优先级原因**: 文档预处理是文档处理流程的基础环节，不同格式的文档需要不同的加载和清洗策略。只有经过预处理的高质量文档内容，才能确保后续解析和索引的准确性。

**独立测试**: 可以上传不同格式的文档（PDF、HTML、DOCX），验证系统能够正确识别格式、加载内容并进行清洗。即使没有后续的解析和索引功能，用户也能看到文档预处理的结果。

**验收场景**: 

1. **给定** 用户上传一个文档文件, **当** 系统接收文档时, **那么** 系统能够识别文档格式（PDF、HTML、DOCX等）
2. **给定** 系统已识别文档格式, **当** 系统加载文档内容时, **那么** 系统使用相应的加载器提取原始内容
3. **给定** 系统已加载文档内容, **当** 系统执行清洗处理时, **那么** 系统去除无关内容（页眉页脚、水印、广告等）、格式化文本、标准化编码
4. **给定** 系统已完成文档预处理, **当** 用户查看预处理结果时, **那么** 用户可以看到清洗后的文档内容和质量报告

---

### 用户故事 2 - 建立本地知识库 (优先级: P1)

用户需要将预处理后的文档内容解析并建立结构化的知识库，系统能够提取文本、结构信息和元数据，建立多模式索引，并支持后续的内容检索。知识库支持多种数据源：1) 用户上传的文档（通过文档预处理流程）；2) 网络检索数据（通过信息源爬取任务获取的网站内容，建立索引后进入知识库）。这是整个系统的基础，没有知识库，其他功能都无法工作。

**优先级原因**: 知识库是系统的数据基础，所有后续的检索和生成功能都依赖于知识库中的内容。必须先建立知识库，才能验证其他Agent的功能。

**独立测试**: 可以通过上传一个或多个预处理后的文档，验证系统能够成功解析文档内容、建立索引，并通过简单的检索查询验证知识库是否正常工作。即使只实现这个功能，用户也能获得一个可用的文档管理系统。

**验收场景**: 

1. **给定** 用户已上传预处理后的文档, **当** 系统开始解析时, **那么** 系统提取文本、结构信息（章节、段落、标题层次）和元数据
2. **给定** 系统正在解析文档, **当** 解析完成后, **那么** 系统建立多模式索引（向量索引、BM25索引、元数据索引、知识图谱），文档内容被索引到知识库中
3. **给定** 知识库中已有文档（包括用户上传的文档和网络检索数据）, **当** 用户执行简单的内容查询时, **那么** 系统能够返回相关的文档片段和来源信息，统一检索所有数据源

---

### 用户故事 3 - 设置硬性规范条件 (优先级: P1)🎯 MVP

用户在开始生成白皮书前，需要设置整份文档的硬性规则和约束条件，这些规则将在后续所有Agent（大纲Agent、信息源匹配Agent、草稿生成Agent）中作为强约束条件执行。

**优先级原因**: 硬性规范条件是整个白皮书生成流程的基础约束，必须在流程开始前确定。这些规则确保生成的文档符合用户的基本要求（报告类型、语言、风格、知识库范围等），是所有后续Agent执行的基础。

**独立测试**: 用户可以设置报告类型、语言、风格、知识库范围等硬性条件，验证系统能够保存这些设置并在后续流程中作为约束条件使用。即使没有其他功能，用户也能完成规范的配置。

**验收场景**: 

1. **给定** 用户开始创建新白皮书, **当** 用户进入规范设置界面时, **那么** 系统显示硬性规范条件设置选项（报告类型、语言、风格、知识库范围等）
2. **给定** 用户选择报告类型（市场研究、政策比对、技术评估等）, **当** 用户确认选择时, **那么** 系统保存报告类型，并作为后续所有Agent的强约束条件
3. **给定** 用户选择平台内置知识库, **当** 用户确认选择时, **那么** 系统将该知识库设置为全流程的强约束条件，后续Agent必须使用该知识库
4. **给定** 用户设置生成过程的语言、风格、范围等要求（报告语言、报告长度目标、是否必须包含图表）, **当** 用户确认设置时, **那么** 系统保存所有硬性要求，并在后续流程中强制执行
5. **给定** 用户已完成硬性规范条件设置, **当** 用户进入后续流程时, **那么** 系统确保所有Agent都遵循这些硬性约束条件

---

### 用户故事 4 - 优化文档大纲结构 (优先级: P2)

用户输入一个初步的文档框架或大纲，系统能够分析这个大纲的结构，识别缺失的部分、逻辑不清晰的地方，并提供结构化的增强建议，帮助用户完善文档框架。系统必须遵循用户在步骤1中设置的硬性规范条件（报告类型、语言、风格等）。

**优先级原因**: 结构优化是文档生成流程的第一步，能够帮助用户明确文档的组织方式，为后续的信息检索和内容生成提供清晰的指导。

**独立测试**: 可以通过输入一个简单的大纲，验证系统能够识别结构问题并提供增强建议。即使没有知识库和生成功能，用户也能获得有价值的大纲优化服务。

**验收场景**: 

1. **给定** 用户已输入一个文档大纲, **当** 用户请求结构优化时, **那么** 系统分析大纲并识别结构问题（如缺失章节、逻辑顺序不当等），同时考虑硬性规范条件中的报告类型要求
2. **给定** 系统已完成结构分析, **当** 系统提供优化建议时, **那么** 用户可以看到增强后的大纲，包括新增的章节建议和结构调整说明，建议符合报告类型的技术模板和写作风格
3. **给定** 用户收到优化建议, **当** 用户接受部分或全部建议时, **那么** 大纲被更新为优化后的版本

---

### 用户故事 5 - 准确可追溯的信息源排名与匹配 (优先级: P2)🎯 MVP

用户基于优化后的大纲，需要从多类信息源中查找与各个章节最相关的原文内容。系统能够检索、排序和匹配信息源，提供可验证、可追溯、可引用的信息源，并支持用户自定义增加素材。用户的选择将作为反馈用于优化排名模型和用户定制化知识偏好。信息源包括：1) 平台内置库；2) 本地知识库（用户上传的文档）；3) 网络检索数据（通过信息源爬取任务获取的网站内容，已建立索引并进入知识库，可统一检索）。

**优先级原因**: 信息源匹配是连接知识库和内容生成的关键环节，能够确保生成的文稿基于真实可靠的信息来源。准确的信息源排名和用户反馈机制能够持续提升系统质量。

**独立测试**: 可以在已有知识库的基础上，针对特定大纲节点进行检索，验证系统能够返回按相关度排序的信息源，并提供可追溯的引用信息。用户可以勾选期望的信息源，系统能够记录反馈。

**验收场景**: 

1. **给定** 用户已拥有优化后的大纲, **当** 用户针对某个大纲节点请求信息源匹配时, **那么** 系统从多类信息源中检索与"大纲节点"最相关的原文内容（平台内置库、本地知识库、用户上传文档、网络检索数据）。网络检索数据通过信息源爬取任务获取，已建立索引并进入知识库，与本地知识库统一检索
2. **给定** 系统检索到多个信息源, **当** 系统进行排序时, **那么** 系统按相关度排序（语义相似度+关键词匹配度+来源可信度），最相关的靠前
3. **给定** 系统返回排序后的信息源, **当** 用户查看结果时, **那么** 每个结果都包含可追溯原文：URL和文件路径可点击跳转、可定位关键段落和页码、提供snippet预览和关键词高亮
4. **给定** 用户查看信息源列表, **当** 用户勾选期望信息源时, **那么** 系统将勾选与拒绝作为feedback，用于迭代排名模型和"用户定制化知识偏好"的长期记忆
5. **给定** 用户需要添加更多素材, **当** 用户手动导入本地知识库（PDF/Docs/Markdown等）时, **那么** 上传后自动进入私有知识库，并提升trust score
6. **给定** 用户需要添加网站数据源, **当** 用户添加自定义网站作为可检索数据源时, **那么** 系统自动爬取该域名指定深度内容，提取正文、去噪，建立页面级和段落级索引，索引后的内容进入知识库，后续检索时与本地知识库统一检索，纳入排名网站库
7. **给定** 用户已勾选、上传或添加内容, **当** 系统更新排名时, **那么** 用户选择的内容默认提升trust score，所有选择形成反馈数据，用于优化检索与排序模型

---

### 用户故事 6 - 生成完整文稿与图表 (优先级: P3)🎯 MVP

用户拥有优化后的大纲和匹配到的信息源（包括本地知识库和网络检索数据），系统能够综合这些输入，生成一篇结构完整、内容充实的文稿，并支持图表自动生成。在草稿编辑界面中，用户可以使用一系列增强工具，包括文本润色、翻译、扩写补写、图表自动生成，以及AI驱动的文稿质量评分与修改建议。信息源包括：1) 本地知识库（用户上传的文档）；2) 网络检索数据（通过信息源爬取任务获取的网站内容，已建立索引并进入知识库）。

**优先级原因**: 文稿生成是系统的最终价值输出，但依赖于前面所有功能的完成。图表生成能力是白皮书生成的核心能力，能够显著提升文档的专业性和可读性。

**独立测试**: 可以在完成前面所有步骤的基础上，验证系统能够基于大纲和信息源生成一篇完整的文稿，并自动识别和生成图表。这是整个系统的完整流程验证。

**验收场景**: 

1. **给定** 用户已拥有优化后的大纲和匹配到的信息源（包括本地知识库和网络检索数据）, **当** 用户请求生成文稿时, **那么** 系统开始综合大纲和信息源生成内容，将前三个步骤（规范约束→大纲优化→信息源匹配）整合为一个可验证、可追溯的专业内容生成引擎。系统统一从知识库中检索信息源，包括用户上传的本地文档和通过信息源爬取任务获取的网络数据
2. **给定** 系统正在生成文稿, **当** 系统识别到可结构化内容（数值、趋势、对比数据）时, **那么** 系统自动生成图表DSL（如ECharts JSON），在草稿中插入图表占位符+可编辑图表配置
3. **给定** 系统已生成文稿草稿, **当** 系统执行基础润色时, **那么** 文稿的语言流畅性、逻辑连贯性和格式规范性得到改善
4. **给定** 系统已生成文稿草稿, **当** 系统检测到表格内容时, **那么** 系统支持表格→Markdown/HTML渲染
5. **给定** 用户查看文稿草稿, **当** 用户进入草稿编辑界面时, **那么** 系统提供左侧多源信息源管理区（展示系统匹配到的所有信息源，高亮显示当前段落实际使用到的来源，点击来源可跳转至原文位置，支持段落级定位）
6. **给定** 用户在草稿编辑界面, **当** 用户使用右侧AI智能检索模块时, **那么** 可将检索结果"一键加入草稿"并自动生成引用链路
7. **给定** 用户在草稿编辑界面, **当** 用户使用中间AI智能分析工具时, **那么** 系统对草稿提供段落级修改建议，支持"一键优化"（按照结构完整度、数据引用完整性、逻辑一致性、专业性指标、可读性评估打分）
8. **给定** 用户查看最终文稿, **当** 用户需要修改时, **那么** 系统允许用户编辑文稿内容，并保留引用信息

### 用户故事 7 - 基于固定模板生成格式文档 (优先级: P3)

用户需要生成符合特定格式要求的文档（如技术报告、学术论文、商业计划书等），系统提供预定义的文档模板，用户选择模板后，系统能够严格按照模板的结构和格式要求生成文稿，确保输出完全符合规范。

**优先级原因**: 许多场景需要严格遵循特定格式规范，基于模板的生成能够确保文档的专业性和规范性，满足标准化文档需求。

**独立测试**: 可以选择一个预定义模板，输入基本内容，验证系统能够生成完全符合模板格式要求的文档。即使没有知识库检索，用户也能获得格式规范的文档生成服务。

**验收场景**: 

1. **给定** 系统提供多个文档模板选项, **当** 用户选择特定模板时, **那么** 系统显示模板的结构和格式要求
2. **给定** 用户已选择模板并输入内容, **当** 用户请求生成文档时, **那么** 系统严格按照模板格式生成文稿
3. **给定** 系统已生成模板文档, **当** 用户查看文档时, **那么** 文档完全符合模板的章节结构、标题样式、引用格式等要求
4. **给定** 用户需要调整模板文档, **当** 用户编辑内容时, **那么** 系统保持模板格式不变，只允许修改内容部分

---

### 用户故事 8 - Homepage与AI智能检索 (优先级: P2)

用户通过主页面访问系统，主页面是整个AI白皮书生成系统的入口，承担白皮书生成流程、一键继续编辑的白皮书历史记录入口、AI智能检索、知识库管理与数据抽取能力的统一呈现。

**优先级原因**: Homepage是用户与系统交互的主要入口，AI智能检索模块能够显著提升问题理解能力和回答质量，是系统的核心价值功能。

**独立测试**: 用户可以通过Homepage访问所有功能模块，使用AI智能检索进行问题查询，验证系统能够返回基于证据的专业分析。用户可以查看历史白皮书记录并继续编辑。

**验收场景**: 

1. **给定** 用户访问系统, **当** 用户进入Homepage时, **那么** 系统显示白皮书生成流程入口、历史记录入口、AI智能检索模块、知识库管理入口
2. **给定** 用户在Homepage使用AI智能检索, **当** 用户输入问题时, **那么** AI智能检索模块通过对多源数据的统一索引与行业语境特征建模，使模型在生成答案前即可加载与问题最相关的原文事实、领域背景与上下文逻辑
3. **给定** 系统返回检索结果, **当** 用户查看答案时, **那么** 系统自动过滤噪声内容、抽取关键要点，并进行结构化重排，使回答从"泛化描述"升级为"基于证据的专业分析"，同时保持简洁、可决策的输出风格
4. **给定** 用户对检索结果进行反馈评价, **当** 用户提交反馈时, **那么** 系统后台保存用户数据作为记忆和学习训练
5. **给定** 用户需要管理知识库, **当** 用户通过Homepage进入知识库管理时, **那么** 系统提供文档管理、数据抽取等能力，支持大规模文档接入、解析与结构化处理
6. **给定** 用户需要继续编辑之前的白皮书, **当** 用户点击历史记录入口时, **那么** 系统显示用户的历史白皮书列表，支持一键继续编辑

### 用户故事 9 - 记忆系统支持人机协作与Agent自我学习 (优先级: P4)

系统能够记录用户在使用平台构建知识库时与大模型的交互历史，包括用户的查询、反馈、操作习惯等，并利用这些记忆不断优化系统性能，提升人机协作效率和Agent的自我学习能力。

**优先级原因**: 记忆系统能够通过记录和分析用户交互，持续优化文档识别准确率、系统提示词、意图识别等关键能力，使系统能够适应不同用户的使用习惯，不断提升协作质量。这是系统的智能化增强功能，可以在核心功能稳定后实现。

**独立测试**: 可以记录用户与系统的交互历史，验证系统能够从交互记录中提取模式，优化文档识别准确率或调整提示词。即使没有其他功能，用户也能看到系统基于交互历史的持续改进。

**验收场景**: 

1. **给定** 用户在使用系统构建知识库时与大模型交互, **当** 系统记录交互过程时, **那么** 系统保存交互历史（查询内容、用户反馈、操作习惯、识别结果等）
2. **给定** 系统已记录足够的交互历史, **当** 系统分析交互模式时, **那么** 系统能够识别用户的使用习惯和偏好，优化系统提示词和交互方式
3. **给定** 系统发现文档识别错误或用户反馈问题, **当** 系统学习改进时, **那么** 系统能够调整识别策略，提升文档识别准确率
4. **给定** 系统记录不同用户的交互模式, **当** 系统为不同用户提供服务时, **那么** 系统能够根据用户历史习惯优化提示词和意图识别，提供个性化体验
5. **给定** 系统持续记录交互历史, **当** Agent执行任务时, **那么** Agent能够参考历史交互记录，自我学习和优化执行策略

### 用户故事 10 - 提示词工程能力 (优先级: P4)

系统提供提示词工程能力，允许用户和管理员创建、编辑、测试和优化用于不同Agent的提示词模板，支持变量替换、条件逻辑、多轮对话等高级功能，并能够基于使用效果持续优化提示词。

**优先级原因**: 提示词质量直接影响Agent的执行效果，提示词工程能力能够帮助用户根据具体场景优化Agent行为，提升系统适应性和效果。这是系统的增强功能，可以在核心功能稳定后实现。

**独立测试**: 可以创建和编辑提示词模板，验证系统能够正确应用提示词、支持变量替换和条件逻辑，并能够测试提示词效果。即使没有其他功能，用户也能获得提示词管理服务。

**验收场景**: 

1. **给定** 用户需要为特定Agent创建提示词, **当** 用户使用提示词编辑器时, **那么** 系统提供提示词模板编辑界面，支持变量、条件逻辑、多轮对话等语法
2. **给定** 用户已创建提示词模板, **当** 用户测试提示词时, **那么** 系统能够使用测试数据执行提示词，展示Agent响应效果
3. **给定** 用户对提示词效果不满意, **当** 用户优化提示词时, **那么** 系统支持版本管理，记录提示词的演进历史
4. **给定** 系统记录了提示词的使用效果, **当** 系统分析提示词性能时, **那么** 系统能够基于使用数据推荐优化建议
5. **给定** 用户需要为不同场景使用不同提示词, **当** 用户配置提示词策略时, **那么** 系统支持根据文档类型、用户偏好等条件自动选择提示词模板

### 边界情况

- **不支持文档格式**: 当用户上传的文档格式不被支持时，系统应明确提示用户当前仅支持PDF、HTML和DOCX格式，并建议用户转换文档格式或等待后续版本支持
- **空知识库检索**: 当知识库为空时，信息检索Agent应返回友好的提示信息，建议用户先上传文档建立知识库，而不是返回空结果或错误
- **大纲复杂度异常**: 当用户输入的大纲过于简单（少于3个章节）时，结构优化Agent应提供基础结构建议；当大纲过于复杂（超过50个章节）时，系统应建议用户拆分文档或分批处理
- **低相关性检索结果**: 当检索结果与大纲主题相关性较低（低于阈值）时，系统应明确告知用户相关性评分，并提供扩展查询建议或建议用户调整查询关键词
- **信息源不足或冲突**: 当生成文稿时发现信息源不足时，系统应标记缺失部分并提示用户补充文档；当发现信息源冲突时，系统应同时呈现不同观点并标注来源，由用户决定采用
- **大文件处理**: 当系统处理大文件（超过10MB）或大量文档（超过100个）时，系统应采用异步处理机制，提供进度反馈，并允许用户继续使用其他功能
- **并发访问**: 当多个用户同时使用系统时，知识库应支持并发读取，写入操作采用队列机制确保数据一致性，每个用户的操作相互隔离

### 功能需求

- **FR-001**: 系统在MVP版本必须支持PDF、HTML和DOCX格式的文档上传，其他文档格式（如Markdown、文本文件等）的加载功能应预留接口，待后续版本实现
- **FR-002**: 系统必须实现文档预处理Agent，能够识别文档格式、加载文档内容，并进行清洗处理（去除页眉页脚、水印、广告等无关内容，格式化文本，标准化编码）

- **FR-004**: 系统必须将解析后的内容建立多模式索引，包括向量索引（用于语义检索）、BM25关键词索引（用于精确匹配和章节定位）、元数据索引（用于按文档属性筛选）和知识图谱（用于结构化关系检索）。知识库支持多种数据源：用户上传的文档和网络检索数据（通过信息源爬取任务获取），统一建立索引
- **FR-034**: 系统必须支持硬性规范条件设置，包括报告类型（市场研究、政策比对、技术评估等）、平台内置用户知识库选择、生成过程的语言、风格、范围等硬性要求（报告语言、报告长度目标、是否必须包含图表等），这些规则必须在后续所有Agent中作为强约束条件执行
- **FR-005**: 系统必须允许用户输入文档大纲或框架
- **FR-006**: 系统必须能够分析大纲的结构完整性、逻辑顺序和内容组织，并考虑硬性规范条件中的报告类型要求
- **FR-007**: 系统必须能够识别大纲中的结构问题（如缺失章节、层次不清、逻辑跳跃等）
- **FR-008**: 系统必须提供结构优化建议，包括新增章节、调整顺序、完善描述等，建议必须符合报告类型的技术模板和写作风格
- **FR-009**: 系统必须支持多种检索模式，包括向量语义检索（理解查询意图，匹配相关内容）、BM25关键词检索（精确匹配关键词，支持章节定位）、元数据检索（按文档属性、章节标签等筛选）和知识图谱检索（基于实体关系查询）
- **FR-010**: 系统必须能够理解用户的检索意图，综合使用多种检索模式匹配相关知识库内容，并根据查询类型自动选择最合适的检索策略
- **FR-011**: 系统必须为每个检索结果提供准确的来源信息（文档名称、章节位置、段落编号、引用标识），支持精确定位到文档的具体位置
- **FR-012**: 系统必须支持检索结果的排序（按相关性、时间、来源等）和筛选（按文档类型、章节、元数据等），并支持混合检索结果的融合排序
- **FR-035**: 系统必须实现信息源排名Agent，能够从多类信息源中检索与"大纲节点"最相关的原文内容，并按相关度排序（语义相似度+关键词匹配度+来源可信度）。信息源包括：平台内置库、本地知识库（用户上传的文档）、网络检索数据（通过信息源爬取任务获取的网站内容，已建立索引并进入知识库）

- **FR-037**: 系统必须支持用户勾选期望信息源，并将勾选与拒绝作为feedback，用于迭代排名模型和"用户定制化知识偏好"的长期记忆

### 关键实体 *(如果功能涉及数据则包含)*

- **文档**: 用户上传的原始文件，包含内容、格式、元数据（文件名、上传时间、大小等）
- **预处理文档**: 经过文档预处理Agent处理后的文档，包含清洗后的内容、质量报告、处理元数据
- **知识库条目**: 解析后的文档内容片段，包含文本内容、结构信息（章节、段落）、索引标识和来源引用
- **向量索引**: 基于语义的向量表示，用于语义相似度检索
- **BM25索引**: 基于关键词的倒排索引，用于精确匹配和章节定位
- **知识图谱**: 从文档中提取的实体和关系网络，包含实体节点、关系边和属性信息
- **记忆条目**: 用户交互记录单元，包含用户查询、系统响应、用户反馈、操作习惯、识别结果、优化策略等，支持版本管理和自我学习
- **文档模板**: 预定义的文档格式规范，包含固定的章节结构、格式要求、样式规范等
- **硬性规范条件**: 整份白皮书的硬性规则，包含报告类型、平台内置用户知识库、生成过程的语言、风格、范围等硬性要求，作为后续所有Agent的强约束条件
- **大纲**: 用户输入的文档框架，包含章节标题、层次结构、描述信息
- **优化后大纲**: 经过结构优化的大纲，包含原始内容、优化建议、新增章节，必须符合硬性规范条件中的报告类型要求
- **信息源匹配结果**: 信息源排名Agent的输出，包含匹配的信息源列表、相关度评分、来源信息、可追溯链接
- **信息源反馈**: 用户对信息源的选择反馈，包含勾选/拒绝的信息源、用户偏好、用于优化排名模型和用户定制化知识偏好
- **自定义数据源**: 用户添加的网站数据源，包含域名、爬取深度、索引状态、信任度评分
- **检索查询**: 用户的检索请求，包含查询关键词、主题、范围限制、检索模式选择
- **检索结果**: 匹配的知识库条目，包含相关内容片段、相关性评分、来源信息、检索模式标识
- **文稿草稿**: 系统生成的初始文稿，包含完整内容、结构、引用信息、图表占位符
- **图表配置**: 文稿中的图表配置，包含图表类型、数据源、DSL配置（如ECharts JSON）、可编辑参数
- **草稿编辑界面状态**: 草稿编辑界面的状态，包含左侧信息源管理区状态、右侧AI检索结果、中间智能分析建议
- **最终文稿**: 经过润色和用户编辑的最终版本，包含所有修改历史和版本信息
- **提示词模板**: Agent使用的提示词模板，包含提示词内容、变量定义、条件逻辑、版本信息、使用效果统计
- **提示词策略**: 根据场景条件选择提示词模板的策略规则，包含条件匹配规则、优先级、应用范围
